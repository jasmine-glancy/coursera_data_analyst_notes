| Concept                                 | Notes                                                                                                                                                                                                                                                                                                                                                                                                 |

| **Data Integrity**                      | - The accuracy, completeness, ​consistency, and trustworthiness of ​data throughout its lifecycle<br>- Can be compromised every time it’s replicated, transferred, or manipulated in any way<br>&emsp;• **Other threats to data integrity** include human error, viruses, malware, hacking, and system failures<br><br>- The data warehouse and data engineering teams can help ensure data integrity |
| **Data Replication**                    | - The process of storing data in multiple locations <br>- This can cause inconsistencies                                                                                                                                                                                                                                                                                                              |
| **Data Transfer**                       | - The process of copying data from a storage device to memory, or from one computer to another <br>- Interrupting this can cause incomplete datasets                                                                                                                                                                                                                                                  |
| **Data Manipulation**                   | - The process of changing data to make it more organized and easier to read<br>- Meant to make data analysis more efficient, but an error during the process can compromise it                                                                                                                                                                                                                        |
| **Data Type**                           | - Values must be of a certain type, such as date, number, percentage, Boolean, etc <br>&emsp;• Ex: If the data type is a date, a single number like 30 would fail the constraint and be invalid                                                                                                                                                                                                       |
| **Data range**                          | - Values must fall between predefined maximum and minimum values <br>&emsp;• Ex: If the data range is 10-20, a value of 30 would fail the constraint and be invalid                                                                                                                                                                                                                                   |
| **Mandatory**                           | - Values can’t be left blank or empty <br>&emsp;• If age is mandatory, that value must be filled in                                                                                                                                                                                                                                                                                                   |
| **Unique**                              | - Values can’t have a duplicate <br>&emsp;• Two people can’t have the same mobile phone number within the same service area                                                                                                                                                                                                                                                                           |
| **Regular expression (regex) patterns** | - Values must match a prescribed pattern <br>&emsp;• A phone number must match ###-###-#### (no other characters allowed)                                                                                                                                                                                                                                                                             |
| **Cross-field validation**              | - Certain conditions for multiple fields must be satisfied <br>&emsp;• Values are percentages and values from multiple fields must add up to 100%                                                                                                                                                                                                                                                     |
| **Primary-key**                         | - (Databases only) value must be unique per column <br>&emsp;• A database table can’t have two rows with the same primary key value. A primary key is an identifier in a database that references a column in which each value is unique. More information about primary and foreign keys is provided later in the program.                                                                           |
| **Set-membership**                      | - (Databases only) values for a column must come from a set of discrete values <br>&emsp;• Value for a column must be set to Yes, No, or Not Applicable                                                                                                                                                                                                                                               |
| **Foreign-key**                         | - (Databases only) values for a column must be unique values coming from a column in another table <br>&emsp;• In a U.S. taxpayer database, the State column must be a valid state or territory with the set of acceptable values defined in a separate States table                                                                                                                                  |
| **Accuracy**                            | - The degree to which the data conforms to the actual entity being measured or described <br>&emsp;• If values for zip codes are validated by street location, the accuracy of the data goes up.                                                                                                                                                                                                      |
| **Completeness**                        | - The degree to which the data contains all desired components or measures <br>&emsp;• If data for personal profiles required hair and eye color, and both are collected, the data is complete.                                                                                                                                                                                                       |
| **Consistency**                         | - The degree to which the data is repeatable from different points of entry or collection <br>&emsp;• If a customer has the same address in the sales and repair databases, the data is consistent.                                                                                                                                                                                                   |
| **Data Integrity Checklist**            | 1. Clean your data<br>2. Check for data integrity<br>3. Check the data you use aligns with the business objective!                                                                                                                                                                                                                                                                                    |
| **Data Alignment**                      | - You can gain powerful insights and make accurate conclusions when the data is well-aligned to the business objectives <br>&emsp;• Good alignment means the data is relevant, can help you solve a business problem, or determine a course of action to achieve a given business objective                                                                                                           |

## Summary

Data integrity involves the accuracy, completeness, consistency, and trustworthiness of data throughout its lifecycle. Data integrity can be compromised via data replication, data transfer, data manipulation, human error, viruses, malware, or system failures. To make data more organized and easier to read, data analysts use data manipulation. Duplicate data occurs when the same information appears in more than one row of a data table.
